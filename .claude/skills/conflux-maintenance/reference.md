# Conflux maintenance: reference

The concrete facts the workflow relies on. Step 8 of every run keeps this file true. Where it disagrees with the tree, the tree wins, and this file gets fixed.

## Layout

- `anchor/`: `anchor.go` (`Supported` = build tag plus a ≥ 5 MiB size check on both binaries; `Digests`, the two SHA-256s `conflux version` prints, stamped by make through `-X …/anchor.anchordSHA256`/`anchorctlSHA256` and computed when a stamp is absent or malformed; `SetID`, the extraction directory's name, 16 hex of `sha256("anchord <d>\nanchorctl <c>\n<GOOS>/<GOARCH>")`), seven build-tagged `bin_<os>_<arch>.go` files (each `//go:embed`s `bin/anchord-<os>-<arch>[.exe]` and `bin/anchorctl-<os>-<arch>[.exe]` by name), `bin_unsupported.go` (every other platform: no pair), `pair_test.go` (the external package `anchor_test`, since `anchortest` imports `anchor`: each binary's header, through `anchortest.Require`), `bin/` (gitignored).

## Make targets

**FIPS 140-3.** `GOFIPS140 ?= v1.26.0`, exported, as anchor's Makefile: every build is against that frozen Go Cryptographic Module with `fips140=on` the default GODEBUG, except OpenBSD's (`GOFIPS140=off`; the module refuses `-fexecute-only` there), chosen per target by the `FIPS` shell function in `build` and `dist`. `GOROOT_BIN` (`GOFIPS140=off go env GOROOT`) puts the go.mod toolchain first on `PATH`, since an installed go older than v1.26.0 stops at "unknown GOFIPS140 version" before switching. `FIPSTEST ?= only` sets `TESTEXEC = -exec 'env GODEBUG=fips140=only'` on `test`, `race` and `golden`. The Makefile is the one place the module version is named: CI's `setup` action reads it into `$GITHUB_ENV` for every job, release.yml's included, and `test/service-bsd.sh` reads it in the VM.

`VERSION` comes from the `VERSION` file and `COMMIT` from `git rev-parse HEAD` (`:=`, so an exported variable cannot restamp them; `make VERSION=x` still can), stamped via ldflags into `internal/version`. `build` and `dist` also stamp each target's two SHA-256s (`STAMP`: `sha256sum` or `shasum -a 256`).

## Binary pipeline

- **`scripts/anchor-bins.sh`**
  - Its targets are the Makefile's `TARGETS`, which `make anchor-bins` hands it in dash form; run without them it refuses, so it is run through make alone. Runs on bash 3.2 (a `docker run bash:3.2` check gives it `TARGETS` as make does).
  - `ONLY="darwin-arm64 …"` narrows any source to those pairs; an unknown target is refused. `DEST` (default `anchor/bin`) moves where they land.
  - It prunes anything in `DEST` that is not one of the 14 names, and the `.anchor-fetch-*` temporaries a killed fetch left.
  - Sources, in order:
    1. `$ANCHOR_SRC/release` (pinned)
    2. `$ANCHOR_SRC/dist` (unpinned; warns loudly)
    3. with `FETCH=1`, anchor's release at `ANCHOR_TAG`, `latest` unless set (`dev-latest` for its dev build; needs `ANCHOR_RELEASE_TOKEN`; failure is fatal)
    4. placeholders
  - It copies and sets `chmod 0755`. The prune is what keeps `anchoradmin-*` out: nothing copies a name that is not one of the 14.
  - Final line: `N/N copied from <src> (release|dist)`, `N/N fetched from anchor's release (pinned build)`, or `N placeholders written to <dest>`, N being 14 without `ONLY`.
  - A local `release/` always beats `FETCH=1`. `ANCHOR_SRC=/nonexistent` forces the fetch.
- **`cmd/anchor-fetch`**
  - Usage: `go run ./cmd/anchor-fetch [-api URL] [-repo owner/name] [-tag T] [-dest DIR] -want a,b,…` (`-dest` defaults to `anchor/bin`).
  - The token comes only from `ANCHOR_RELEASE_TOKEN`.
  - Logs to stderr: `release:`, `commit:` (the release's `target_commitish`, which anchor sets to the commit SHA), `realm:` (the pin), one line per file with its digest and `fetched` or `cached`, then `N/N in place, digests verified`.
- **`internal/anchorrelease`**
  - Source: GitHub API, repo `veil-net/anchor`, tag `latest` unless `-tag` names another. `latest` moves; it names the newest build from anchor `main`, which anchor also releases at a dated tag `YYYYMMDD-HHMMSS` that stays. `dev-latest` is the pre-release of the newest build from anchor `dev`, which conflux's `dev`, and every PR into it, embeds; the `anchor-bins` action takes it as `tag:`, and CI picks it by the PR's base (`version3` → `latest`, anything else → `dev-latest`), with a self-hosted cache directory per tag.
  - It refuses any `anchoradmin*` asset and any asset not in state `uploaded`.
  - It reads `manifest.json`: `{"formatVersion":1,"pin":"realm…","binaries":[{"name","program","os","arch","bytes","sha256"}]}`, held to the `sha256:` digest the release document gives for it (it arrives through the same storage redirect as the binaries). There are no URLs; assets are resolved by name within the one release.
  - A file already at the destination with the manifest's size and SHA-256 is kept (`cached`); anything else is downloaded to a temp file, checked for size and SHA-256, and renamed into place.
  - Every file at once; the first failure cancels the rest and is the one reported. `ok` lines arrive in completion order. All 14 fresh: ~6 s (37 s one at a time); cached: ~1 s.
  - The API and every redirect are held to `config.CheckAPIURL`: HTTPS, or plain HTTP with `CONFLUX_ALLOW_INSECURE_API=1` (`config.InsecureAPIEnv`) for tests; at most 5 redirects.
  - Bounds: manifest 1 MiB, binary 200 MiB.

## Anchor's release build

- **`make release`**
  - Prerequisites: `.bin/garble` (built from anchor's `tools/go.mod`) and `$(GENESIS_DIR)/genesis.pin`, where `GENESIS_DIR ?= genesis`.
  - **When the pin file is absent, its rule mints a new genesis root** (writes `genesis.key`, `genesis.pub`, `genesis.pin`). Anchor's own CI writes the pin from a public repository variable, `GENESIS_PIN` on `main` and `GENESIS_PIN_DEV` on `dev`, and asserts afterwards that no `genesis.key` appeared. Step 3 mirrors that. A local checkout's `genesis/` may hold exactly such a minted development root, whose pin is neither tree's.
  - It first runs `rm -rf release/`. Then, for each anchor `DIST_TARGETS` entry (linux/amd64, linux/arm64, darwin/amd64, darwin/arm64, windows/amd64, windows/arm64, freebsd/amd64, openbsd/amd64), with `CGO_ENABLED=0 GOWORK=off`, it builds three programs:
    - `anchord`, garbled, with `-ldflags -X github.com/veil-net/anchor.pinnedGenesis=<pin>`
    - `anchorctl`, garbled, `-tags lockdown`
    - `anchoradmin`, plain and unrestricted, **always**
  - Output: `release/{anchord,anchorctl,anchoradmin}-<os>-<arch>[.exe]`, 24 files, then `release: 24 binaries in release/, pinned to realm…`. About 25 s with a warm build cache.
  - Garbled builds are not byte-reproducible, so a local release and anchor's release built from the same commit have different digests.
  - darwin/amd64 is not in conflux's `TARGETS`, and `anchor-bins.sh` ignores it.
- **`make dist`:** the unpinned, unobfuscated cross-build for the same 8 targets. Only `anchord` and the `-tags lockdown` `anchorctl` go into `dist/` (16 files). It joins any realm tree: development only, never shippable.
- **`scripts/client-is-locked.sh DIR [ADMIN_DIR]`:** runs the host's `DIR/anchorctl-<os>-<arch> root` with no daemon and requires the lockdown refusal (`unknown command "root"`). Fails if any `anchorctl` is byte-identical to its `anchoradmin` twin in `ADMIN_DIR`.
- **Release publishing:** anchor's `release.yml` publishes every pull request's merge into anchor `main` or `dev`, never a direct push (its `merged` job, as conflux's); on `dev` it publishes one pre-release, `dev-latest`, with the same assets and manifest and nothing dated, and after a release of `main` merges `main` back into anchor's `dev`. It runs `make release` with the branch's pin, `GENESIS_PIN` on `main` and `GENESIS_PIN_DEV` on `dev` (two realms, on purpose), then `scripts/release-manifest.sh` (copies `anchord`/`anchorctl` only, runs `client-is-locked.sh`, writes `manifest.json`, whose `pin` is that pin), then `scripts/publish-release.sh` twice with the same assets and notes: at a dated tag `YYYYMMDD-HHMMSS` (the commit's time in UTC; it stays) and at `latest`, which moves and is marked Latest. Each is deleted and recreated with `target_commitish` set to the commit SHA; on `dev` the build is also uploaded as a workflow artifact, kept 30 days.

## Live traveller API

The schema is served by Swagger UI at `/docs`. The OpenAPI 3.0 document is embedded as `swaggerDoc` in `/docs/swagger-ui-init.js`; `/openapi.json` and similar paths return 404. Extract it:

```bash
python3 - "$S" <<'EOF'
import json, sys, pathlib
d = pathlib.Path(sys.argv[1]); s = (d / 'swagger-ui-init.js').read_text()
i = s.index('"swaggerDoc":') + len('"swaggerDoc":')
doc, _ = json.JSONDecoder().raw_decode(s[i:].lstrip())
(d / 'openapi.json').write_text(json.dumps(doc, indent=1, sort_keys=True))
for p, ops in sorted(doc['paths'].items()):
    for m, op in ops.items():
        print(m.upper(), p, op.get('tags'), sorted(op.get('responses', {})))
EOF
```

**Routes conflux calls** (the only ones this skill may call):

- `POST /ghosts/alpha`: body `{"taints": [...]}` (`EnrolAlphaDto`, required; at most 32 names matching `^[^\s@+\p{C}]+$`; empty is the realm's shared compartment), no auth. Returns `201 {"credentials": "<base64 anchor manifest>"}` (`GhostCredentialsResponseDto_Output`, no other properties). The credential commits to the taints and lasts thirty days, nothing is stored server-side, and the response is the only copy.
- `POST /ghosts/alpha/renew`: body `{"anchorId": "anchor…", "taints": [...]}` (`RenewAlphaCredentialDto`; anchorId pattern `^anchor.*`, max 128; the taints the anchor was enrolled with, since nothing records them and the running anchor refuses another set). Returns `200 {"chain": "<base64>", "notAfter": "<date-time>", "bootstrap": [...]}` (`GhostRenewalResponseDto_Output`, all required; bootstrap read afresh, as `anchorId@host:port` or `host:port`; live it answers `["genesis.veilnet.com.au:4700"]`). Unauthenticated; renew on launch and at two thirds of `notAfter`.

The schema documents only success responses. A refusal is NestJS's `{"message": …, "error": …, "statusCode": …}` — the renewal route answers a malformed AnchorID with `400 {"message":"member: id: wrong length: want 58 characters, got 28",…}` — and `enrol.HTTPError` shows the message.

**Enrolment check** (step 2; one call):

```bash
curl -sS -X POST -H 'Accept: application/json' -H 'Content-Type: application/json' -d "{\"taints\":[\"$T\"]}" \
  -o "$S/alpha.json" -w '%{http_code} %{time_total}s\n' "$API/ghosts/alpha"   # expect 201
python3 - "$S/alpha.json" <<'EOF'
import json, sys, base64
m = json.loads(base64.b64decode(json.load(open(sys.argv[1]))['credentials']))
secret = {'identity', 'chain', 'renewalSecret'}
print(json.dumps({k: '<redacted>' if k in secret else v for k, v in m.items()}, indent=1))
EOF
```

Expected fields, in the order the API sends them:
- `formatVersion: 1`, `kind: "anchor"`
- `realm` (hex), `genesis`, `identity` and `chain` present
- `notAfter` and `issuedAt` in `2006-01-02T15:04:05.000Z` form, about thirty days apart (`issuedAt` is written just after the chain is signed, so the window is a fraction of a second short of thirty days)
- `taints: ["$T"]` (the request, echoed), `useExit: false`, `bootstrap` holding the tree's genesis node (`genesis.veilnet.com.au:4701` on dev, `:4700` on production) after any nodes of its own; no `telemetrySecret`
- `renewalUrl` = `$API/ghosts/alpha/renew` (same host)
- `renewalAuth: "anchor-id"`

Check every field against `internal/enrol` and anchor's `anchorManifest`. Never print `identity`. Delete `$S/alpha.json` at the end.

**Pin** (step 3): the pin is the realm the dev genesis derives to: `realm` plus lowercase unpadded base32 of `SHA3-256("veilnet/anchor/id/v1" || 0x00 || suite 0x01 || genesis)`, anchor's `internal/id` `Derive`. It must equal the pin anchor publishes for its `dev-latest` pre-release (`GENESIS_PIN_DEV`; `latest` is pinned to production's `GENESIS_PIN`, a different realm on purpose), the `pin` in that release's manifest, which `anchor-fetch` prints as `realm:` after fetching one binary into scratch (any token that can read anchor's releases, in the environment):

```bash
PIN=$(python3 - "$S/alpha.json" <<'EOF'
import json, sys, base64, hashlib
g = bytes.fromhex(json.loads(base64.b64decode(json.load(open(sys.argv[1]))['credentials']))['genesis'])
print('realm' + base64.b32encode(hashlib.sha3_256(b'veilnet/anchor/id/v1\x00\x01' + g).digest()).decode().lower().rstrip('='))
EOF
)
ANCHOR_RELEASE_TOKEN=… go run ./cmd/anchor-fetch -tag dev-latest -dest "$S/release" -want anchord-linux-amd64 2>&1 | grep -E '^(commit|realm):'   # realm: must be $PIN
```

**Guardian contracts** (read in the schema, never call):

- Conflux's self-hosted guardian renewal: the manifest carries `renewalAuth: "node-secret"` and `renewalSecret: "<nodeId>.<secret>"`, sent verbatim as `Authorization: Bearer …` to the manifest's same-host `renewalUrl` on the guardian's own API, with the alpha renewal's body and answer (`{anchorId, taints}` to `{chain, notAfter, bootstrap}`). That route is not in traveller's schema; conflux follows the manifest. The guardian node-manifest fields conflux also reads (`ipv4`, `export`) are defined in a sibling repository's contract (`docs/credentials.md` links it), not in the schema.
- `POST /guardians/{id}/delegation`: `Authorization: Bearer <guardianId>.<secret>` (the guardian credentials' `renewalToken`). Returns `{chain, link, notAfter, severedAt}`. Every refusal is the same 403.
- `GET /orgs/{orgId}/guardians/{id}/credentials`: the base64 guardian credentials document (realm root to pin, guardian realm root with its private key, delegation, bootstrap, renewal) that a guardian stack ingests.
- `GET /ghosts/realms/{realm}/nodes/{id}/credentials`: the base64 node document (realm, anchor key, credential, taints, run flags) for veilnet's own `alpha`/`beta` infrastructure nodes.

Schema quirks: only a `firebase` oauth2 security scheme is declared, `guardian-token` is referenced without being declared, and most authenticated routes carry no `security` field. Decide what is authenticated from each route's description, not from `security`.

**Never call** anything else, including `/`, `/health`, `/genesis*`, `/ghosts/realms*`, `/ghosts/me*` (including `/ghosts/me/beta*` and `/ghosts/me/backups*`), `/auth*`, `/orgs*`, `/guardians*`, `/anchor/release*`, `/billing*` and `/users*`. (`GET /anchor/release` answers traveller's conflux shelf, a `ReleaseDto`, and on api-dev `POST /anchor/release/update` moves it; neither is conflux's binary source, which is conflux's own GitHub releases.)

## Probe node

A single live node from the freshly built image, used in step 3 (pin proof, the one renewal), for the step 5 baseline (a fresh probe after `make image` if step 4 changed anything), and for the step 7 after numbers.

```bash
docker rm -f cfx-probe >/dev/null 2>&1 || true
docker run -d --name cfx-probe --privileged --cgroupns=host \
  -v /sys/fs/cgroup:/sys/fs/cgroup:rw --device /dev/net/tun conflux-systemd-test
for _ in $(seq 40); do [ "$(docker exec cfx-probe systemctl is-system-running 2>/dev/null)" = running ] && break; sleep 1; done
time docker exec cfx-probe conflux up --api "$API" --taint "$T" --no-ipv4   # enrolment + bring-up to ready; no TTY, so --ipv4 or --no-ipv4 is required
docker exec cfx-probe conflux status
time docker exec cfx-probe conflux renew                        # the renewal round trip plus hot install
```

- Behind an egress proxy that re-signs TLS, append its CA to the container's `/etc/ssl/certs/ca-certificates.crt` (`docker cp`, then `cat >>`) before `up`.
- Where outbound HTTPS goes only through a local proxy (`HTTPS_PROXY` on the host, plain HTTP refused): `make image` cannot reach Debian's mirrors over http, so build it against a local `debian:trixie-slim` of the same tag, made in scratch with the proxy CA copied in, the sources switched to https and `Acquire::https::CAInfo` set, with `docker build --network host --build-arg http_proxy=$HTTPS_PROXY --build-arg https_proxy=$HTTPS_PROXY` (the repository's Dockerfile is never edited). Run the probe `--network host` in proxy mode (no TUN), give the service the proxy with `systemctl set-environment HTTPS_PROXY=… SSL_CERT_FILE=<the CA>` and each `docker exec` the same with `-e`. UDP to the bootstrap node may be blocked there too: the node then starts under the pin and renews, with `peers=0`, and CI's `integration` is what proves the join.
- Docker Hub rate-limits shared hosts: pull a base from `mirror.gcr.io/library/<image>` and tag it locally (`bash:3.2` likewise).
- For after numbers, copy the old binary in beside the new (`docker cp`) and interleave them: `status` ten times each, `down`/`start` several times each (`up`'s wait polls every 100 ms, so three of each is noise).
- Where Docker has no IPv6, a TUN `up` cannot start: use `conflux proxy --api "$API" --taint "$T" --no-ipv4 8080=127.0.0.1:3000`, which proves the pin and the renewal the same way.
- `serve` beside the running service must be refused ("another conflux supervisor is already serving …", exit 1).

## Sub-agents

Step 6's auditors and fixers are sub-agents. What they are told is all they know, so a brief names the goal, the scope (the area, or the commits of a changes audit), the files to read first (this skill's three files), the constraints below, and the report wanted. An auditor is handed no conclusion, and a finding it reports is a claim that whoever makes it re-derives from the code.

- **Read-only, here and in anchor.** An agent changes nothing in the main checkout, and nothing in anchor ever (rule 2). A fixer works in a worktree cut by hand from the branch HEAD (`git worktree add -b <name> "$S/<name>" HEAD`) and confirms `git rev-parse HEAD` first: an agent tool's own worktree isolation cuts from the default branch, `version3`. The HEAD moves while it works, so its branch is rebased onto the HEAD as it is then and taken by fast-forward, its diff checked first; a comment-only change is checked by comparing the Go tokens with comments stripped.
- **A scratch directory of its own** under `$S`, for every temporary file: agents running at once overwrite a common name. Read every taken commit's message for text that is not about its change.
- **No auditor starts while a fixer works.** An audit reads a tree nothing is being changed in: every fixer's branch is taken, built and vetted before the next round's auditors are started (SKILL.md, step 6).
- **The rules bind them.** Rule 10 holds for every agent that touches the live API, and rule 12 for every commit one makes. A design question an agent meets goes back to the main session, which asks the user; the agent goes on with what does not depend on it.
- **Taken in turn, branches can rebase cleanly and still not compile together.** Build and vet after each is taken, and run the tests of the areas both touched. A run started in the background before a branch was taken tests the tree as it was compiled, not the tree after it.
- **A hash a commit message cites changes with a rebase.** Cite a commit by its subject where it can move, and check before a push that every hash a message on the branch cites is on the branch.
- **They share the host's CPUs.** Pin each agent's runs to CPUs of its own (`taskset -c`), and take a timing only where nothing else runs.
